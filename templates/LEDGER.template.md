# Ledger — [Applicant Name]

The ledger is the master source for every tailored document, score and
application answer. Edit the ledger when a fact changes; never edit a
tailored document to introduce a fact that is not here.

## Fact-status markers

Every fact in this ledger carries one status. Only **user-attested** and
**confirmed** facts may be used for matching or drafting.

- `[attested]` — user-attested: the applicant stated it directly.
- `[confirmed]` — confirmed: extracted from a source document and reviewed
  by the applicant.
- `[pending]` — pending: imported, not yet reviewed. **Not usable.**
- `[conflicted]` — conflicted: contradictory evidence exists. **Not usable**
  until resolved; keep both values and their sources.
- `[retired]` — retired: historical, no longer current. **Not usable** for
  current claims; kept for history.

A correction preserves the old value in a history note and flags every
dependent package for re-review.

## Missing-number convention

Never invent a number. Where a STAR entry needs a quantified result that is
not yet known, write the missing value in brackets — for example
`[x]%`, `[n] samples`, `[date]` — and ask the applicant for it. A bracketed
placeholder must never survive into a presented document.

## 15. Style guide

Format, scoring and feedback rules that carry across every package, so
later packages improve instead of restarting.

- Document format: `templates/FORMAT-STANDARD.md` (one consistent format;
  never invent a layout).
- Fit threshold: score at or above the threshold in
  `templates/FIT-SCORECARD.md` enters the ranked shortlist.
- Grammar gate: every CV, resume and cover letter passes a dedicated
  proofreading pass before it is presented.
- Applicant feedback log (classify each item before saving):
  - Factual correction → this ledger, with provenance.
  - Wording / formatting preference → this style guide; global only when
    the applicant explicitly makes it general.
  - Job-specific inclusion decision → that opening's package only.
