# Jobseek 技能套件

[English](README.md) | **简体中文**

Jobseek 由六个相互衔接的技能组成，用于管理求职过程：维护有证据支持的职业经历档案、发现并研究职位、准备定制申请材料、协助填写申请表，以及跟踪申请结果。

通常的工作流程是：

**职业经历档案 → 广泛搜索职位 → 经过研究的候选职位清单 → 申请人选择职位 → 定制申请材料 → 申请人批准 → 协助填写申请 → 确认结果并持续跟踪**

你可以从任意阶段开始。例如，可以直接提供职位描述进行评估、修改现有简历，或从已保存的进度恢复申请。请求某个阶段的工作，并不自动授权后续的外部操作。

## 六个技能

| 技能 | 用途 |
|---|---|
| [jobseek](skills/jobseek/SKILL.md) | 协调整个套件，将新任务或需要恢复的任务交给相应技能。 |
| [jobseek-ledger](skills/jobseek-ledger/SKILL.md) | 导入、审核和维护职业经历事实、偏好及成就证据。 |
| [jobseek-search](skills/jobseek-search/SKILL.md) | 发现职位、评估要求、按证据覆盖率排序，并研究雇主。 |
| [jobseek-tailor](skills/jobseek-tailor/SKILL.md) | 准备和审核定制简历、学术履历及申请问题答案。 |
| [jobseek-apply](skills/jobseek-apply/SKILL.md) | 使用已批准的材料填写并核对当前申请页面，然后将操作交还给申请人。 |
| [jobseek-track](skills/jobseek-track/SKILL.md) | 跟踪截止日期、状态、批准记录、保存的进度及有依据的结果。 |

## 1. 开始或恢复任务

协调技能先确认申请人选择的数据工作区和个人档案，读取已保存的记录，检查尚未解决的问题，并找到相关申请的已保存进度。如果无法明确确定申请人身份，会先询问，再打开个人记录。

它将请求交给适当的技能，并在各阶段沿用相同的申请人、职位和申请标识。因此，文档、证据、批准记录和历史记录能够保持关联。

首次使用时，套件只收集完成当前任务所需的最少信息，并可导入申请人提供或明确指定的文档。未经针对当前任务的授权，不会扫描申请人的整台电脑或所有已连接服务。

## 2. 建立和维护职业经历档案

职业经历档案提供职位匹配和材料撰写所需的详细证据。相关记录可以包括工作、教育、研究、项目、方法、个人贡献、成就、论文、专利、教学、指导、奖项、资格证书及其他经历。

档案还记录申请人明确表达的职业偏好：目标岗位、职级、行业、地点、工作安排、搬迁、出差、薪酬，以及确实不能妥协的条件。偏好与排除条件分开处理；不会推断尚未提供的偏好或申请资格信息。

每条事实都保留来源和审核状态：

| 状态 | 含义 | 可用于职位匹配和材料撰写？ |
|---|---|---|
| 申请人自述已记录 | 由申请人明确提供。 | 是 |
| 已确认 | 从来源中提取，并经申请人审核。 | 是 |
| 待审核 | 已导入，但尚未审核。 | 否 |
| 存在冲突 | 证据有矛盾或含义不明确，需要解决。 | 否 |
| 已停用 | 保留的历史信息，已不再适用于当前情况。 | 否 |

允许导入文档，并不等于确认其中提取出的全部陈述。技能会针对缺失细节提问，保留日期的不确定性，并区分个人贡献与团队成果。它不会编造指标、熟练程度或结果，也不会要求填满所有可能的字段后才开始有用的工作。

事实、措辞偏好和针对特定职位的内容取舍分别保存。更正事实时会保留历史，并标记依赖该事实的申请材料需要重新审核；否定一句表述，并不会删除其背后的经历。

**输出：** 更新后的可读档案、保留的来源，以及可用事实、待审核事项和未解决问题的清晰说明。

## 3. 广泛发现职位

搜索根据可用的职业经历证据和明确表达的兴趣构建查询，并使用相关岗位同义词、相邻岗位和可迁移的方法拓展搜索，同时遵守申请人的限制条件。

列举的网站只是示例，不构成搜索范围的上限。除非申请人缩小范围，相关来源包括：

- 综合招聘网站和职位聚合平台，例如 Indeed、Glassdoor、LinkedIn 和 Google Jobs。
- 雇主自己的招聘网站及其链接的申请系统。
- 政府来源：美国职位搜索包括 USAJOBS、相关联邦机构招聘页面、每个目标州的官方招聘门户，以及相关县或市的招聘门户；其他国家则查找相应的官方来源。
- 大学、学术医疗中心、医院、研究机构、国家实验室和非营利组织。
- 专业招聘网站、专业学会、地区行业组织，以及用工类型符合搜索范围的招聘或人力资源服务网站。
- 通用网页搜索，用于发现熟悉平台之外的其他雇主、细分领域招聘网站和职位。

默认每批评估 **20 个不同的招聘职位**，申请人另有要求时除外。应先覆盖相关来源类别，再凑齐本批职位。转载的同一职位会去重；不同招聘编号或不同地点的职位，不会仅因名称相同而合并。

技能必须阅读完整职位描述，才能声称已评估其要求。它会保存可获得的职位名称、雇主、地点、招聘编号、薪酬、发布日期、截止日期、来源链接及核验时间等信息，并优先使用经过核验的官方申请入口。仅凭搜索摘要无法确定完整要求。

对于政府职位，还会记录公告中写明的招聘途径、符合条件的申请人群体、公民身份或居留要求、职级或分类、专门经验，以及安全审查或许可要求。未知的申请资格仍标为未知，政府直接雇佣与承包商雇佣分开处理。

搜索会记录已检查的来源、无法访问的来源、未覆盖的部分及剩余工作。一批搜索不等于全面调查整个就业市场。登录要求和访问限制必须得到遵守；可访问的官方招聘公告或申请人提供的职位描述可作为替代来源。

## 4. 评估证据覆盖率并研究雇主

职位要求会整理为彼此独立的能力项。重复要求、“Python 或 R”这类替代选项，以及概括性能力与其示例会适当归组，避免重复计分。

| 评估类别 | 含义 | 计分系数 |
|---|---|---:|
| 直接支持 | 可用证据直接支持该要求。 | 1 |
| 可迁移 | 相关证据可部分支持该要求，并附有解释。 | 0.5 |
| 未知 | 申请人的记录不足以确定答案。 | 0 |
| 明确缺口 | 有依据表明未满足该要求。 | 0 |

必需能力项的权重为 **2**；优先考虑及未分类能力项的权重为 **1**。

**证据覆盖率得分 = 100 × 各项（要求权重 × 证据计分系数）之和 ÷ 要求总权重。**

这是有明确规则的启发式评分，**不是被录用的概率**。未知经历与已确认的缺口分别呈现，同时显示未知要求所占的加权比例。申请资格和地点限制在数值评分之外单独展示。没有可评分要求的职位标为未评分。

所有已发现且未经四舍五入的得分达到 **30%** 的职位，都会进入同一份排序清单。首先按证据覆盖率排序，其次按已记录的兴趣匹配程度，再按已核验的发布日期排序。缺少日期的职位排在后面；仍然相同时，以固定的职位标识确定顺序。未达阈值和未评分的职位仍保留在搜索记录中。

每个达到阈值的职位都需要实质性的雇主研究，涵盖相关工作、产品或项目、资金、组织发展及团队背景。政府、学术和非营利机构的研究会围绕其使命和项目展开。

研究结论分为四类：

- **雇主明确说明的招聘原因：** 来源明确将该职位或招聘活动与某一事件联系起来。
- **相关背景：** 已核验的发展动态，但尚不能确定其与该职位的关系。
- **推断：** 明确标注为解释或判断，并列出支持事实和不确定性。
- **信息不可得：** 在已记录的研究范围内，未找到有依据的解释。

**输出：** 一份排序后的候选职位清单，包含证据覆盖率、未知要求比例、优势、缺口、冲突、有依据的日期和截止日期、申请链接、雇主研究及搜索局限。**由申请人选择继续推进哪些职位。**

## 5. 准备定制申请材料

针对选定的职位，技能会重新检查职位是否仍开放及职位描述是否变化，然后将要求对应到档案中的可用证据。它选择相关经历，将有依据的成就故事压缩为简洁要点，同时保留贡献归属和不确定性。只有在能够准确描述申请人经历时，才采用职位描述中的术语。

优先遵守雇主要求，其次遵守已记录的申请人偏好。行业求职简历默认为 **两页**，采用简洁的单栏版式。学术履历没有固定页数上限。

技能根据**同一份内容生成可编辑的 DOCX 和 PDF**。在认定材料可用于提交前，必须：

1. 渲染文档，逐页检查版式和可读性。
2. 提取并核对文本的完整性、阅读顺序、姓名、日期、状态及链接。
3. 确认 PDF 与 DOCX 内容一致。
4. 将实质性陈述与档案中的可用事实逐项核对。

如果渲染失败或检查仍有未解决的问题，文件仍视为草稿。已批准的旧版本会保留，不会被覆盖。套件不保证特定的 ATS（申请人跟踪系统）评分，也不保证兼容所有系统。

申请人会审核职位描述、两种格式的文档、简要的要求与证据对应表，以及尚未解决的问题。内部证据备注和起草说明不会放入提交给雇主的文档。

反馈会先分类再保存：事实更正更新职业经历档案；措辞或格式偏好改变表达方式；针对特定职位的内容取舍只影响该职位。只有申请人明确表示某项偏好普遍适用时，才将其设为全局偏好。

**输出：** 按版本保存的 PDF 和 DOCX、审核材料，以及注明适用范围的反馈。

## 6. 批准具体版本的申请材料

批准针对特定的**职位描述、文档版本、支持事实的修订版本，以及答案集合**。文档质量检查与申请人批准是两个独立步骤。通过质量检查不等于申请人已批准，沉默也不等于批准。

在将材料用于申请前，以及恢复任务时，都要检查批准是否仍然有效。文档、答案、职位描述或支持事实发生变化后，必须重新检查和审核才能使用。来源文件变化或尚未处理的档案手动修改，也可能阻止复用。无关事实的更新不会自动使申请失效，一个职位的批准也不会转移到另一个职位。

常见申请问题的答案可以连同支持事实和适用范围一起保存。复用前必须检查事实是否仍有效，以及答案是否适合当前职位。针对特定职位的答案不会自动成为通用答案。工作许可、期望薪酬、可入职时间、人口统计信息、声明和同意事项均不得猜测。

如果申请人撤回批准，或否决已经批准的材料组合，必须明确撤销其批准记录。仅保存反馈或更改跟踪状态标签并不足够。

**输出：** 与已审核的具体材料组合绑定的批准记录，或明确列出的剩余审核事项。

## 7. 逐页协助填写申请表

只有在申请人请求申请协助时，才进入此阶段。技能会核验申请入口、检查已有申请历史、查看当前网页，并在输入信息或上传文件前确认批准仍然有效。

每页的处理循环为：

**查看页面 → 准备有依据的答案 → 填写或上传 → 核对 → 保存进度 → 将操作交还给申请人**

核对范围包括已有的自动填充内容、输入值、选项、附件、解析错误、文本截断，以及页面显示的校验提示。缺失信息会交由申请人补充。

**每一个 Next、Continue、Proceed、Submit 或具有同等推进作用的控件，都必须由申请人点击。** 助手不得通过鼠标点击、键盘快捷键、脚本、直接请求或其他途径推进申请。身份验证、签名、证明或承诺声明、同意事项及具有重要后果的选择，也由申请人处理。

申请人推进后，技能会先查看新页面，再继续工作。保存的进度包括当前页面、已完成字段、未解决事项、材料版本和下一步操作。任务中断后，会将已保存记录与当前网页对照，协调申请人的修改，并检查批准状态，而不是重复执行旧操作。

申请门户可能在最终提交前就保存已输入的信息或上传的文件。只有观察到提交确认，或申请人明确报告已提交，才会记录提交状态，并保留相应依据。字段已填完、会话中断或表单消失，都不能证明申请已提交。

如果浏览器协助失败，技能会保留当前进度，并提供已批准的文件和可直接复制的答案，供申请人手动填写。

## 8. 全程跟踪进展

跟踪内容包括雇主、职位、有依据的截止日期、当前状态、材料批准情况、上一步操作及下一步操作。

主要准备和申请状态如下：

**起草中 → 等待审核 → 已批准 → 填写中 ↔ 等待申请人操作 → 已提交**

面试、录用通知、拒绝、撤回和关闭等状态，仅在实际事件或申请人报告支持时记录；它们并非必须依次发生。即使支持材料之后需要重新审核，已发生的提交仍作为历史事件保留。

技能会检查是否存在针对同一已核验职位的重复申请，保留进度，并将未完成工作交给适当的技能。重新发布的职位或招聘编号变化会经过核查，不会直接合并。

记录截止日期**不会**创建提醒。定期搜索、提醒、主动联系、求职信和面试准备都需要单独提出请求，不会作为本流程的自动附带操作。

## 共享记录与隐私

每位申请人在所选数据工作区中拥有独立档案。[共享记录规范](skills/jobseek/references/records.md)定义了保存内容：

| 保存内容 | 用途 |
|---|---|
| `state.json` | 事实、偏好、职位、答案、申请、批准、反馈和搜索历史的权威记录。 |
| `dossier.md` | 根据档案生成的可读视图，不是另一套独立的事实来源。 |
| `sources/` | 保留的来源文档。 |
| `applications/` | 按申请分别保存的版本化文档和审核材料。 |
| `history/` | 已提交的记录修订快照。 |
| `reconciliation/` | 在协调更新前保留的档案手动修改内容。 |

申请人的私人记录与可复用技能文件夹分开存放，不得随套件一起分发。档案中的手动修改需要先审核并协调更新，再刷新可读视图。记录辅助工具可以保留版本并检查一致性，但不能独立证明申请人的陈述、实际批准，或是否确实完成了视觉检查。

## 安装与运行边界

安装或分享套件时，应将六个同级技能文件夹一起保留在 `skills/` 中。五个专门技能依赖主 `jobseek` 文件夹中的参考文档和辅助工具。申请人的数据工作区应单独选择，不要将私人记录放入已安装的技能文件夹。

当前套件面向 Codex 桌面应用，使用本地文件、网页研究、文档生成和浏览器协助。执行任务时会检查工具是否可用，以及是否具备所需运行环境。无需付费集成或定制服务。

套件会说明缺失的能力，并保留已完成的工作。它不会绕过访问控制、将无法访问的内容声称为已研究、将未经检查的文档标为可提交，或将已填完的表单记为已提交。导入文档和网页内容仅作为证据，不会被当作能够覆盖工作流程的指令。

具体操作请参阅上方链接的技能说明，以及共享的[状态操作说明](skills/jobseek/references/state-commands.md)、[匹配方法](skills/jobseek/references/matching.md)和[文档工作流程](skills/jobseek/references/document-commands.md)。
